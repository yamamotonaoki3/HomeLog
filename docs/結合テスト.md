# テスト実行手順

[← 要件定義書に戻る](requirements.md)

Cloudflare Workers 版のテストの種類と実行方法。CI（GitHub Actions）でも同じものを実行するが、PR を作る前に手元でも実行する。

> 当初の Java 版（`backend/`）では Testcontainers（PostgreSQL 17）による結合テストを使っていた。Workers 版では、バックエンドの単体テスト自体が本物の D1 に対して API を呼ぶため、別の結合テスト環境は持たない。

---

## 1. 種類

| 種類 | 場所 | 内容 |
| --- | --- | --- |
| バックエンド単体テスト | `backend-workers/src/test/` | Vitest ＋ `@cloudflare/vitest-pool-workers`。miniflare 上の本物の D1 にマイグレーションを適用し、Hono アプリへ HTTP リクエストを送って検証する |
| フロントエンド単体テスト | `frontend/src/test/` | Vitest ＋ jsdom ＋ Testing Library。API は msw で差し替える |
| E2E | `e2e/tests/` | Playwright。ローカルの Workers（8787）と Vite（5181）を起動し、画面操作と API を通しで確認する。画面は 1280 / 390 / 320px で確認する |

## 2. 前提

- `backend-workers/.dev.vars` に `JWT_SECRET` 等を設定する（`.dev.vars.example` を参考にする。値はコミットしない）。
- E2E は 8787・5181 番ポートを使うため、手元の開発サーバーは止めておく。

## 3. 実行コマンド

```bash
# バックエンド
cd backend-workers
npm run lint
npm run typecheck
npm test

# フロントエンド
cd frontend
npm run lint
npx tsc -b
npx vitest run
npm run build

# E2E（先にフロントエンドをビルドしておく）
cd e2e
npm test                          # すべて
npm test -- tests/warikan.spec.ts # 1ファイルだけ
```

## 4. テストデータ

- ユーザー名・メールは `e2euser_` / `testuser_` 接頭辞と `@example.com`、本文は `[E2E_TEST]` タグを付ける（実データ・個人情報は使わない）。
- E2E は実行後に `e2e/scripts/cleanup.mjs` でローカルの E2E 用データを削除し、残数が 0 であることを確認する。
