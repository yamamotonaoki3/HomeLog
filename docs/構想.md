# シェファミ 全体構想書

## 1. アプリの目的
個人の財政管理を行いながら、1世帯内で協力して購入したものの精算・食材等の在庫管理を一括で行えるアプリ。

## 2. 想定ユーザー像
- 単位は「個人」。ただし「世帯グループ」を作成し、世帯内での精算・共有管理を行う。
- 個人財政は個人が管理し、世帯全体としての合算財政は管理しない（世帯としての家計簿は持たない）。
- 世帯管理では、協力購入した物品やお金の貸し借りの精算関係を管理する。
- シェアハウスのような、家族に限らない複数人同居でも利用できることを想定。
- 将来的に自分・家族以外の第三者にも公開する可能性がある。

## 3. 各機能の概要

### 3-1. 家計簿
- 個人の支出管理：日時、金額、使用用途、カテゴリー、支払った人、メモを登録可能
- 個人の収入管理：日時、金額、内容、カテゴリー、メモを登録可能。収入－支出で個人の収支を把握できる
- 世帯で割り勘したものの精算関係の管理
- 世帯に関係のない相手（世帯外の人）との割り勘・精算管理も可能にしたい
- 固定費（水道・光熱費・家賃・ネット代・携帯料金等）を毎月の支払日とともに登録できる
- 「イベント」と「支出」をセットで登録できる（例：サークル会費1,000円）
- カテゴリー別の支出検索
- イベントごとの使用金額をTOP画面等ですぐ確認できる機能（例：父の日、推し活などの用途ごとに金額を集計表示）

### 3-2. 食材の在庫管理
- 在庫管理項目：品名、カテゴリー、買う店（任意）、個数（小数点第一位まで入力可）、買い物リストへの追加閾値（個数）を登録
- 在庫が閾値以下になったら自動的に買い物リストへ追加
- 買い物リストの並び替え：あいうえお順／カテゴリー順／買う店順
- 買い物リストでの購入チェックと購入個数の入力
- 「購入を反映」で確認後、購入数を在庫へ一括加算する。予定数の未購入分はリストに残し、買い切った手動品目と、買い切って在庫が閾値を上回った自動品目は除外する（詳細は[F-08](details/features/F08_zaiko_shoppinglist.md)）

### 3-3. 献立表
- レシピ登録（手書きレシピを画像解析でテキスト化して登録する機能を含む）
- WEB上のレシピをURL貼り付けで引用登録
- お気に入りレシピ登録
- WEBレシピ登録時に自分用メモ（例：「塩を足す」等）を残せる
- 登録済みレシピ／WEBレシピまたは自由メモを週単位の献立リストとして登録（曜日への割り当ては行わない）

## 4. 機能間の連携方針
- **献立表 ⇔ 在庫管理**：品目ごとに連携を選び、手持ちの在庫を料理別の残り予定回数として割り当てる。回数は整数で、予定の合計は在庫以内とする。料理名・メモ・翌週への持ち越しを設定できる。「食べた」の記録1回で在庫を1個、該当する予定を1回減らし、直前の食事から取り消せる。レシピに書かれた材料と在庫の自動照合は行わない。
- **在庫管理 ⇔ 買い物リスト**：密連携。在庫が閾値以下になると自動的に買い物リストに追加され、購入更新時に在庫へ反映される（3-2参照）。
- **買い物リスト ⇔ 家計簿**：連携なし。買い物リスト以外の支出も多いため、自動連携はしない。

## 5. データ構造の方針
- 在庫管理と買い物リストは共通のデータ（同一テーブル/密連携）として扱う。
- 家計簿は独立したテーブル群で管理する。在庫品目と献立の連携は、在庫・レシピ・週の献立を関連付けて管理する。

## 6. マルチユーザー・権限に関する考慮点
- 世帯グループ単位でユーザーを管理するマルチユーザー構成。
- 個人の家計簿・口座・カードデータは本人のみが閲覧・編集可能（他の世帯メンバーは閲覧・編集不可）。
- 割り勘・立て替えの精算は、支払いを受ける側（相手）が承認しないと「精算済み」にならない（承認フロー必須）。
- 在庫管理・献立登録には権限制限を設けず、世帯メンバーであれば誰でも自由に操作可能。
- データ分離（他世帯のデータに一切アクセスできないようにするアクセス制御設計）は、技術スタック検討時に詳細を詰める。

## 構想時の次のステップ（対応済み）
1. 家計簿・在庫管理・献立表それぞれの詳細要件定義書を個別に作成（優先順位はユーザーと相談）
2. 技術スタック（フレームワーク・DB構成等）の相談・決定

### 在庫の日次自動消費（#329）

在庫ごとに任意の1日の消費量とオン／オフを保存し、毎日JST 1:00に自動で減らす。開始・再開は翌日から、オフ期間は消費せず、数量は0で止める。停止・消費量変更時には到来済みの未処理分を旧設定で精算する。消費後の閾値以下判定で買い物リストへ連携する。残り予定回数の合計が0より大きい場合、または有効な旧関連がある場合は、日次自動消費をオンにできない。合計が0で有効な旧関連がなければ、献立連携がオンでも日次自動消費を設定できる。詳細は[在庫管理](details/features/F07_zaiko_inventory.md)を参照。
