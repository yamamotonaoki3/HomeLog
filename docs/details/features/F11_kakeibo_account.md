# F-11 口座・カード管理

[← 要件定義書に戻る](../../requirements.md)

---

## 1. 概要

銀行口座・PayPay等の電子マネーを「口座」として手動登録し、支出登録時にどの口座から出費したかを選択できるようにする。カードは口座に紐づく子エンティティとして扱い、以下2種別を持つ。

- **クレジットカード（`credit`）**：カード自体は残高を持たず、支払いは常に紐づく親口座から引き落とされる（従来仕様）。
- **チャージ型カード（`charge`）**：Suica等の電子マネーカードのように、カード自体が**独立した残高**を持つ。口座からチャージ（資金移動）することで残高が増え、支払いはカード自身の残高から減算される。

今回のスコープは手動登録のみとし、外部API連携（銀行・カード会社・Money Forward ME・PayPay等）は対象外とする（[common-notes.md](../common-notes.md) 7章参照）。

口座は**残高**を持ち、個人の財政管理に用いる。残高は所有者本人のみ閲覧可能（[common-notes.md](../common-notes.md) 2章：個人データの権限方針）で、当該口座を指定した支出を登録するたびに自動的に減算される。チャージ型カードの残高も同様に所有者本人のみ閲覧可能な個人財政情報として扱う。

## 4. IPO

### 口座登録

| 項目 | 内容 |
| --- | --- |
| 入力 | 口座名・種別（`bank`/`e_money`等）・初期残高 |
| 処理 | accounts テーブルに保存（owner_user_idはログインユーザー、balanceに初期残高を設定） |
| 出力 | 登録した口座 |

### カード登録

| 項目 | 内容 |
| --- | --- |
| 入力 | 紐づける口座ID・カード名・種別（`credit`/`charge`、既定は`credit`） |
| 処理 | cards テーブルに `account_id`・`card_type` を設定して保存（`charge`型は`balance`を0で初期化） |
| 出力 | 登録したカード |

種別は登録後に変更不可（`charge`型に残高が積まれた状態で`credit`型へ変更すると資金の扱いが不定になるため）。

### チャージ実行（charge型カードのみ）

| 項目 | 内容 |
| --- | --- |
| 入力 | 対象カードID・チャージ元口座ID・金額 |
| 処理 | チャージ元口座の残高からチャージ金額を減算し、対象カードの残高に加算する。`card_charges` テーブルに履歴として記録する（家計簿の支出・収入一覧とは別管理）。排他制御は口座→カードの順でロックを取得する |
| 出力 | 更新後の口座残高・カード残高、チャージ履歴 |

残高不足時の制御は設けない（5章の口座残高マイナス許容方針と同様）。

### 支出登録時の口座/カード選択

| 項目 | 内容 |
| --- | --- |
| 入力 | 支出情報・口座ID または カードID（任意） |
| 処理 | credit型カード or 口座直接指定の場合：expenses.account_id に設定して保存 → 選択された口座（カード選択時はカードの親口座）のbalanceから支出金額を自動減算。charge型カードの場合：expenses.card_id に設定して保存 → カード自身のbalanceから支出金額を自動減算（口座残高は変化しない） |
| 出力 | 口座/カードが紐付いた支出（残高はレスポンスに含めない。画面は登録後に口座一覧を取得し直して最新残高を表示する。実装に合わせて修正、#305） |

### 口座の取引履歴表示（S-15）

S-15 で口座名をクリックすると、その口座の取引履歴をモーダルで表示する。

| 項目 | 内容 |
| --- | --- |
| 入力 | 口座ID |
| 処理 | 口座の所有者本人のみ取得可能（他人の口座は404）。口座残高を増減させる次の3ソースを日付降順（同日は登録順の降順）で1つの一覧にまとめる：`expenses.account_id`（支出、出金）／`incomes.account_id`（収入、入金。通常収入と割り勘精算）／`card_charges.from_account_id`（チャージ元、出金）。各行に「その取引直後の残高」を、現在残高から新しい取引順に符号付き差分を遡って再構成する（残高を動かすのはこの3ソースのみ。支出・収入を編集・削除すると残高も同じ差分だけ補正されるため（#275）、現在の明細から正確に逆算できる） |
| 出力 | 現在残高、取引一覧（日付・内容・種別（支出/収入/チャージ）・金額（±）・取引後残高） |

## 5. 口座残高と個人財政管理

### 口座への収入入金と削除（#244）

- 新規の通常収入は同世帯・本人所有の有効口座が必須。収入INSERTと残高の相対加算を単一D1 batchで確定する（F-13参照）。取引履歴の入金は通常収入と精算収入の両方を含む。
- 固定費が口座または子カードを参照する場合、引き落とし先として利用中のため削除不可。残高が0でない子カードがある場合も削除不可。
- 上記の禁止対象がなければ、過去の支出・収入（通常/割り勘精算）・チャージ・割り勘支払元の参照があっても削除できる（#368）。子カード経由の履歴も含め、参照があれば`accounts.deleted_at`を設定して204を返す。口座のID・名前・残高、子カード、履歴・精算状態を保持する。これらの参照がなければ従来どおり物理削除する。
- 論理削除済み口座とその子カードは一覧・選択肢・残高合計から除外し、新規の収入・支出・カード登録・チャージ・固定費・精算先には指定できない。口座の編集・再削除・取引履歴取得は404。支払報告後に論理削除された支払元口座は、従来の物理削除時と同様に精算確定時には口座なしとして扱う。
- 収入GETは論理削除された口座も含めて`accountName`を解決する。UI対応は#245。既存の収入・精算収入・残高は遡及変更しない。
- 削除と取引登録の競合でもこの方針を維持する。削除batch内で固定費参照・子カード残高・履歴の有無を再確認し、取引書き込み時にはDBトリガーで削除済み口座への新規参照・残高更新を拒否する。先に確定した過去取引は保持して論理削除し、先に削除された口座への取引は400とし、同一batchの履歴・残高・精算状態をすべて取り消す。

- 残高は口座の所有者（owner_user_id）本人のみが閲覧・登録・編集できる（他の世帯メンバーには表示しない）。在庫管理・献立表と異なり、口座・残高は世帯共有ではなく個人管理の情報として扱う。
- 支出登録時に口座/カードを選択すると、当該口座（またはchargeカード）の残高が支出金額分だけ自動的に減算される。残高が支出金額を下回りマイナスになる場合の制御は設けない（今後の検討事項）。
- 個人全体の財政状況を一目で確認できるよう、トップ画面（S-04）の「個人の財政」カードに自分が所有する口座の残高合計を表示する（[wireframes.md](../wireframes.md) S-04参照）。チャージ型カードの残高も口座からチャージされただけで個人資産であることに変わりないため、この合計に含める。

## 7. 今後の検討事項

- 外部API連携（Money Forward ME等の家計簿連携サービス経由でのカード・PayPay利用明細の自動取得）
  - 銀行・カード会社の公式APIは提携審査・契約が必要なケースが多く、個人開発では実現のハードルが高いため、まずは家計簿連携サービスのAPI活用を軸に検討する
- 口座の所有者（owner_user_id）以外の世帯メンバーが、その口座を使った支出を登録できるかどうかの権限整理
- 残高がマイナスになる場合の入力制御・警告表示の要否
- 口座残高の手動修正（実際の残高とのズレを補正する機能）の要否
- チャージ型カード自体の取引履歴（カードでの支出・チャージ入金）の一覧表示。口座側の取引履歴（4章）は実装済みだが、カード側は未対応
- チャージ履歴（`card_charges`）の一覧表示API・UI（今回は記録のみでUIは対象外）
- 口座間の直接振替（チャージ以外の資金移動）への拡張
