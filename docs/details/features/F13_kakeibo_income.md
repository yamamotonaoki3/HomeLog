# F-13 個人収入管理

[← 要件定義書に戻る](../../requirements.md)

---

## 1. 概要

個人の収入（給与・ボーナス・副業収入等）を記録し、カテゴリー別に検索できる（[common-notes.md](../common-notes.md) 2章：本人のみ編集可能）。[F03_kakeibo_expense](F03_kakeibo_expense.md)（個人支出管理）と対になる機能で、トップ画面（S-04）の「収支」表示は収入合計－支出合計で算出する（[common-notes.md](../common-notes.md) 8章参照）。

世帯で管理したいのは「共同で行った買い物・イベント等の支出を割り勘・精算しやすくすること」「今月の共同支出の内訳を把握すること」であり、収入を世帯で合算・共有する必要はない。そのため収入は**純粋に個人管理**とし、支出のような世帯合計対象フラグ・世帯合計への算入の仕組みは持たない（[common-notes.md](../common-notes.md) 8章参照）。

## 4. IPO

### 収入登録

| 項目 | 内容 |
| --- | --- |
| 入力 | 日時（必須）・金額（必須）・内容（必須）・カテゴリー（必須）・入金先口座（必須）・メモ（任意） |
| 処理 | 入力チェック → incomesへの口座ID付きINSERTと口座残高の相対加算を単一D1 batchで原子的に実行 |
| 出力 | 登録した収入オブジェクト / エラーメッセージ |

### カテゴリー別検索

| 項目 | 内容 |
| --- | --- |
| 入力 | カテゴリーID |
| 処理 | incomes テーブルを category_id で検索 |
| 出力 | 該当する収入一覧 |

## 5. 入力チェック仕様

| 項目 | 必須 | 形式・制約 |
| --- | --- | --- |
| 日時 | ○ | 日付形式 |
| 金額 | ○ | 1〜9,999,999,999の整数 |
| 内容 | ○ | 1〜100文字 |
| カテゴリー | ○ | income_categories から選択 |
| 入金先口座 | ○ | 同世帯かつ本人所有の未削除口座から選択。カードは指定しない。省略・null・不正IDは400 |
| メモ | — | 0〜255文字 |

## 6. 権限方針

支出（F-03）と同様、**本人のみ閲覧・編集可能**とする。他の世帯メンバーは個々の収入データを閲覧できない（[common-notes.md](../common-notes.md) 2章）。支払った人に相当する項目（＝収入を得た人）は本人固定とし、選択式にはしない（F-03の`payer_user_id`と同じ設計思想。他人を選択できてしまうと権限方針と矛盾するため）。

## 7. カテゴリーマスタ初期リスト

給与／ボーナス／副業／その他（[common-notes.md](../common-notes.md) 11章参照）

## 7-2. カテゴリー管理（追加・編集・削除）

S-05（家計簿一覧画面）ツールバーの「カテゴリー管理」リンクからS-23（家計簿カテゴリー管理画面）に遷移し、収入カテゴリーを自分で追加・編集・削除できる。

- 7章の初期リストは**デフォルトカテゴリー**として世帯単位で初回アクセス時に冪等シードされ、編集・削除できない。
- ユーザーは**カスタムカテゴリー**を追加できる。名前は1〜50文字必須。
- カスタムカテゴリーは編集（名前変更）・削除ができるが、既に収入（`incomes`）に紐づいて使用中のカテゴリーは削除できない（先に付け替えが必要）。
- API：`GET/POST/PATCH/DELETE /api/income-categories`（バックエンド実装済み）。収入口座連携の契約は[api-design.md](../api-design.md)を参照。

## 8-2. 一覧・詳細閲覧（Issue #214）

- S-05は全モードで日付・内容・金額の3列。収入金額は「+1,000円」と既存の緑系配色で表示する。
- ネイティブbutton＋span/gridの行全体（日付・内容・金額・余白を含む）のタップ、行ボタンのEnter／Spaceで収入詳細を開く。同じ数値IDの支出と収入も種別を含めて区別する。
- 詳細は日付・内容・金額・種別・カテゴリー・口座・メモを表示する。通常収入・精算収入とも入金先口座を表示し、過去の`accountId: null`は「なし」とする。収入GETの`accountName`は論理削除済み口座の名前も返す。
- 世帯合計対象・割り勘内訳は表示しない。詳細下部に「編集」「閉じる」、既存の削除が可能な場合だけ対象名付き右上ゴミ箱を表示する（#277/#422 partial）。編集は既存値入りの登録モーダルで行い、種別は変更できない。保存後は再取得した詳細へ戻る。削除は「この操作は取り消せません」を含む確認ダイアログを経て行い、成功後は詳細を閉じる。保存・削除後は一覧・口座残高・割り勘を再取得し、トーストを表示する。400/409のAPIメッセージはモーダル内のアラートとして表示する。
- 閉じる・Escape・背景タップで閉じ、行ボタンへフォーカスを戻す。

## 8-3. 口座連携（#244 / #245）

- #244でAPIの入金先必須化・残高連動・論理削除口座の名前解決を実装する。入力UIと削除済み口座の名前表示は#245で対応する。
- 既存の通常収入（NULL口座）・精算収入・口座残高は遡及変更しない。精算による自動収入は従来の任意口座のまま。
- 新規登録時の加算結果に新たな残高上限は設けない。残高の再取得は`GET /api/accounts`を使用する。
- 収入が参照する口座は論理削除し、一覧・選択肢・残高合計から除外する。収入の口座IDと名前は保持する（F-11参照）。

## #422 家計簿UIと前回口座の記憶

- 履歴の既存全期間取得・新しい順を維持し、キーワード/収支/対象月と既存カテゴリーで絞り込む。当月サマリーは年月を明示し、当月収入・支出・差額を表示する。履歴のfilterで会計対象や当月合計を再定義しない。上部の開始操作は「収支を登録」とする。
- 基本の日時・金額・用途/内容・カテゴリー・支払元/入金先は常時表示し、支出の世帯合計/イベント/割り勘/メモ、収入のメモを「その他の設定」へまとめる。開閉で値や送信bodyを変えず、編集は元明細を優先する。新規登録の支払元/入金先は、同じbrowser内で利用者別・収入/支出別に記憶した前回の成功選択を初期候補にする。編集は元明細を優先する。
- 既存詳細の削除を右上へ移し、確認を省略しない。親詳細は編集/確認中hiddenで保持して最上位の子へキー操作を譲る。取消/終了後の起点focus、API失敗・保存/削除成功後GET失敗の区別、請求中/精算済の操作制限を維持する。登録・編集フォームへ新しい削除経路は追加しない。

- 前回口座の記憶は利用者ID・収支種別ごとに分け、口座/カードの種別とID、または明示未選択だけをbrowserに保存する。口座名・残高・明細・認証情報は保存しない。ログアウトで記憶は消さず、別利用者へ候補や未保存入力を引き継がない。
- 記憶は登録/更新APIの成功時だけ更新する。取消・入力エラー・API失敗では変えず、成功後の一覧再取得失敗は登録済みと区別し、記憶も成功選択を維持する。保存中に利用者が変わった場合の旧応答は、新利用者の記憶や画面に反映しない。
- 新規の初回・本人未確定・記憶破損・削除済みなど使用不能な候補は未選択とし、先頭口座を自動選択しない。収入はカードを選択できず、有効な口座が必須。支出の明示解除も保存成功時に記憶する。口座取得中/失敗を候補消失と扱わず、遅い候補取得で利用者の手動変更/解除を上書きしない。browserの記憶機能へのアクセス失敗は通常の登録/更新の成否を変えない。
