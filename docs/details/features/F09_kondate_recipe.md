# F-09 レシピ登録・管理

[← 要件定義書に戻る](../../requirements.md)

## 1. 概要

レシピの手動登録・手書きレシピの画像解析登録・WEBレシピの引用登録・お気に入り管理を行う。

### PCの閲覧ページから登録（#222）

- S-12に「PCからレシピを登録」の案内と、ドラッグ可能な「HomeLogに登録」リンクを表示する。
- ブックマークバーを表示し、リンクをドラッグして設置する。レシピの閲覧ページで設置したブックマークを押すと、設置時のHomeLogのorigin（HTTP/HTTPS・ポートを含む）の `/recipes/share?url=...` を別タブで開く。元ページは保持し、URL以外の本文・認証情報は送らない。
- S-13のWEBタブに閲覧URLを入力した状態で開き、ユーザーが「登録」を押して初めて既存APIへ保存する。案内内のリンクを通常クリックした場合は遷移せず設置方法を表示する。
- 世帯所属済みユーザーは、未ログインならログイン後（失敗後の再試行を含む）に共有URLへ復帰する。世帯未所属ユーザーの世帯作成・参加後の復帰は対象外。
- 通常のHTTP(S)ページを対象とする。ブラウザ内部ページやCSP等により使えないページでは、既存のWEBタブへのURL貼り付けを案内する。
- 案内はモバイルでも折り返して表示する。既存のURL長制限・API・データモデルは変更しない。

### iPhoneの共有から登録（#223）

- S-12のPC案内の下に「iPhoneからレシピを登録」と「ショートカットを追加する」の入口を表示する。端末を問わず閲覧可能。
- `/recipes/iphone-shortcut` は既存の認証・世帯ガードとAppLayoutを使う案内ページとし、レシピ一覧へ戻れる。
- ページ先頭の「ショートカットを追加」ボタンで、ユーザーが作成した「HomeLogに登録」ショートカットのiCloud共有リンクを新しいタブで開く（本番URL向け、#271）。追加後の使い方（共有メニューから選ぶ・初回は許可・登録画面で確認して登録）と、使えない場合のWEBタブへのURL貼り付けを案内する。自作手順は画面に表示しない（#273）。
- Safariやアプリの共有から実行すると既存のWEB登録画面がURL入力済みで開く。内容確認後の登録操作で初めて保存する。未ログインからの復帰も既存の共有契約を使う。
- 新API・DB変更は含めない。

#### 配布ショートカットの構成（作り直す場合の記録）

- 共有シートでURL／Safari Webページ／テキスト（アプリ内の共有用）を受け取り、入力がなければ停止する。
- 入力からURLを取得し、URLだけをクエリ値として1回エンコードする。
- 「テキスト」で `https://<本番ホスト>/recipes/share?url=` の直後にエンコード結果の変数を連結し、「URLを開く」へ渡す。
- 作り直したらiCloudリンクを再発行し、`RecipeIphoneShortcutPage.tsx` のリンクを差し替える（古いリンクは古い内容のまま配布される）。

## 5. データ設計（関連テーブル）

[data-model.md](../data-model.md) の `recipes` テーブルを参照。

### WEBレシピのタイトル・サムネイル自動取得方式（実装済み）

`POST /api/recipes/from-url` に登録先URLを渡すと、サーバー側でそのURLをfetchし、
`HTMLRewriter` で `<meta property="og:title">` / `<meta property="og:image">` / `<title>` を
ストリーミング抽出する（レスポンスボディを丸ごとメモリに読み込まない）。

- YouTube（youtube.com・youtu.be・m.youtube.com・music.youtube.com）のURLは、Workersからページを取得すると同意画面などが返りタイトルが「YouTube」になるため、YouTubeの oEmbed API から動画タイトルとサムネイルを取得する。失敗したときは下記のHTML解析に戻る（#285）
- タイトルは `og:title` → `<title>` → URL文字列 の優先順で必ず何か確定する
- サムネイルは `og:image` が無ければ保存しない（NULL）
- `http:`/`https:` 以外のスキーム、`localhost`/ループバック/プライベートIP帯を指定したURL、
  非HTMLレスポンス、fetch失敗（タイムアウト・DNS失敗・非2xx）は400エラーとする（SSRF対策）
- 取得したタイトル・サムネイル・元URL・任意メモを `source_type='web'` で保存する
  （材料・手順は保持しない）。以降の編集はメモのみ可能

### 共有ボタン連携（PWA、実装済み）

インストール済みPWA（主にAndroid Chrome）から、他アプリの共有メニュー経由でレシピURLを
HomeLogへ渡せる（Web Share Target）。共有すると `/recipes/share?url=...` に遷移し、
WEBタブが選択された状態でレシピ登録モーダルが自動的に開く。`url`パラメータが無い場合は
`text`パラメータからURLらしき文字列を正規表現で抽出してフォールバックする。
iOS SafariはWeb Share Target非対応のため、iOSはショートカット案内 または URL貼り付けで登録する。

### 手書きレシピの画像解析（実装済み）

- `POST /api/recipes/ocr/upload` で画像を R2 に一時保存し、`POST /api/recipes/ocr/analyze` で解析する。
- 文字認識は Google Cloud Vision、認識した文字の「タイトル・材料・手順」への整理は Workers AI（LLM）で行う。結果は S-13 の確認フォームに入れ、ユーザーが確認・編集してから `source_type=ocr` で保存する。
- 一時保存した画像は日次処理で削除する。
