# ワイヤーフレーム

[← 要件定義書に戻る](../requirements.md)

S-01〜S-24の全画面・モーダルについて、要件定義段階の骨組みレベルでワイヤーフレームをまとめる。実際のUIデザイン（配色・フォント・詳細CSS）の決定前段階の「叩き台」として、ASCIIアート風のレイアウト図で画面内の要素配置・サイズ感を示し、補足としてMermaidのブロック図（要素の関係性）も併記する。各画面の項目は対応する[機能別要件定義書](../requirements.md#5-機能要件)の内容に基づく。

## 共通ヘッダー（#257）

世帯所属後の各画面では、左にHomeLogロゴ、右に通知・設定・アカウント群を配置する。アカウント群は上にログイン本人の表示名、下にログアウトボタンを右寄せで表示する。

- 表示名は `GET /api/auth/me` から取得し、メールや世帯の別メンバー名は代用しない。
- 長い名前は1行で省略し、DOMとtitle属性に全文を保持する。320pxでも操作部品とページ全体が横にはみ出さない。
- 取得中は「読み込み中…」、失敗時は「アカウント名を取得できません」。取得状態によらず設定・ログアウトを利用できる。
- 世帯未所属画面へのヘッダー追加や、名前編集・全文表示専用UIは対象外。

- カレンダーの各日付セルの具体的な情報密度・アイコンデザインは未定。今後の詳細検討事項とする。
- 通知アラームはトップナビゲーションに配置し、通知有効な繰り返しイベントの当日発生件数をバッジで表示する。カレンダー内には通知件数を表示しない。取得中は読み込み状態、取得失敗時はエラー状態を件数と区別して表示する。
- モバイルではカレンダーと有効なカードを保存順に1列へ積み、横方向のスクロールや固定ナビゲーションとの重なりを生じさせない。カードの表示/非表示設定、カード内項目、カード順は画面幅にかかわらず維持する。
- 「イベント別支出」カードは**期間セレクト（今日／今月／今年、デフォルト今年）**を持つ。「年間投資」は投資専用集計ではなく、暦年（今年）のイベント別支出を意味する。他のカードにイベント別支出を含めない。
- 未精算は「受取予定（自分が立て替えて相手から貰う分）」と「支払予定（自分が負担して相手に払う分）」を分けて表示する。
- 「個人の財政」カードは自分が所有する口座の残高合計を表示し、その下の行に「口座・カード管理を見る」リンク（S-15、`/accounts`）を配置する。読み込み中・取得失敗・口座未登録でもリンクを表示する。口座残高は本人のみ閲覧可能のため、このカードの内容もログインユーザー自身の情報のみで構成される（[common-notes.md](common-notes.md) 2章、[F11_kakeibo_account](features/F11_kakeibo_account.md)参照）。
- イベント別支出には全イベントではなく、**表示対象として選択したイベント（`show_on_dashboard` = true）のみ**を表示する。ON/OFFはS-18登録モーダル・S-09一覧から直接開く編集モーダル内で登録者が他の項目と一緒に保存する（[F06_kakeibo_event](features/F06_kakeibo_event.md) 4章参照）。
- 「買い物・在庫」カードは買い物リストを「品名／値段」、在庫リストを「品名／残数」の見出し付き2列で表示する。買い物は未購入のみ、在庫は残数と閾値以下の「（不足）」を表示する。値段は現在の参考値を桁区切りの円表示（0は「0円」、未設定は「未設定」）とし、数量との乗算はしない。在庫欄には値段を表示しない。品名とカード末尾にリンクを設けず、管理画面へは主要ナビゲーションから移動する。先頭8件と残件数、読み込み中・空・取得失敗、表示設定とカード順を維持し、長い品名と値は320pxでも全文を折り返して横にはみ出させない。「よく使う品目」は廃止する。
- 「今日の状況」カードは今週の献立を簡潔なリストで表示する。レシピIDとタイトルがある項目はボタンとし、クリック・Enter・Spaceで既存レシピ詳細モーダルを閲覧専用で開く。既存 `GET /recipes` の一覧から `summary.weeklyMenuEntries.recipeId` で選択し、編集・削除ボタンは表示しない（S-12では従来どおり表示）。自由メモ・削除済みレシピは操作できない文字列として表示する。
- レシピ取得中は献立ボタンの多重操作を防ぎ、取得失敗・対象消失はトーストで通知する。詳細は閉じるボタン・Escape・背景クリックで閉じ、元の献立ボタンへフォーカスを戻す。モーダル内部のクリックでは閉じない。長いタイトル・材料・手順は狭い画面でも折り返す。
- イベント名はボタンとして表示し、クリックでS-24イベント詳細モーダルを開く。イベントボタンのクリックは日付クリック（S-19）を発火させない。S-24は閲覧専用で、編集・削除ボタンや編集遷移は提供しない。
- 各カードの数値・リンク先は、対応する各機能画面の情報をそのまま参照する（新たな計算ロジックは持たない）。
- 「収支」（今日の状況カード・カレンダー各日付セル）は、ログインユーザー本人のその日の収入合計－支出合計。支出側の世帯合計対象フラグの有無に関わらず本人が登録した全件を対象とし、他メンバーの収入・支出は権限方針上参照できないため常に本人個人の収支となる（世帯合計支出とは別の指標。[common-notes.md](common-notes.md) 8章、[F13_kakeibo_income](features/F13_kakeibo_income.md)参照）。
- どのカード（今日の状況／買い物・在庫／個人の財政／今月のお金／イベント別支出／カレンダー）を表示するかに加え、カード内の項目単位でも設定画面（S-21）でユーザーごとに表示を選択できる。カレンダーは表示ONなら最上部、OFFなら非表示とする。全カードを非表示にした場合は設定画面への案内を表示する。
- S-21のチェックリスト下には有効カードをコンテナとして並べる編集グリッドを表示する。ドラッグ操作でカード順を変更でき、キーボード利用者には上へ／下へ移動ボタンまたは同等の操作を提供する。保存時に表示設定とカード順を同一トランザクションで保存し、成功後はS-04へ遷移する。失敗時はS-21に留まり、変更内容を保持してエラーを表示する。

詳細閲覧（Issue #214）：

- 金額は収入を緑系の「+1,000円」、支出を既存支出配色の「-1,000円」と表示し、色だけに頼らない。
- 行ボタンのEnter／Space、日付・金額セルを含む行タップで詳細を開く。空用途は「内容なし」。3列を維持し、320pxでもページ全体の横はみ出しを防ぐ。
- 支出詳細：日付・内容・金額・種別・カテゴリー・口座／チャージ型カード・世帯合計対象・イベント・メモ・割り勘内訳（相手・割合／負担額・状態）。creditカードは親口座を表示する。
- 収入詳細：日付・内容・金額・種別・カテゴリー・口座・メモ。通常収入と精算収入の入金先を表示し、既存の`accountId: null`は「なし」。論理削除済み口座の名前は収入GETの`accountName`で解決する（#244 API対応、表示UIは#245）。世帯合計対象・割り勘内訳は表示しない。
- 割り勘は当該支出の支払者側内訳に限定し、読み込み中・取得失敗・0件を区別する。
- 閉じる・Escape・背景タップで閉じ、元の行ボタンへフォーカスを戻す。編集・削除ボタンは表示しない。支出／収入そのものの編集・削除とAPIは別Issueで検討する。


- 表示設定は「カード（親）」と「カード内項目（子）」の2階層で選択でき、カード順も保存できる（`user_settings.dashboard_settings`、[data-model.md](data-model.md)参照）。

## S-10 在庫の自動消費入力（#329）

登録・編集モーダルの閾値欄の後に、次を縦配置する。

```text
1日の消費量（任意） [0.2]
空欄の場合は自動消費しません
[自動消費：オン / オフ] （role=switch）
毎日1:00（日本時間）に減ります。開始・再開は翌日から。
停止・消費量変更時は到来済みの未処理分を旧設定で精算します。
[保存] [キャンセル]
```

number入力はstep=0.1/min=0.1/max=99999.9。空欄でスイッチはオフ・無効、オフにしても消費量は保持する。登録初回入力でオン、その後の選択は維持する。詳細に「自動消費：未設定／0.2／日・オン／0.2／日・オフ」を追加する。一覧は品名・在庫数・閾値の3列のままとし、行ボタン内にスイッチは置かない。

1280/390/320pxで説明を折り返し、モーダル内の縦スクロールで保存へ到達できる。Tab巡回、Spaceでの切替、Escape・背景クリック、通信中の無効化とフォーカス復帰を維持する。保存失敗はrole=alertで入力を保持し、保存成功後の一覧取得失敗では保存を再送しない。
