# ワイヤーフレーム

[← 要件定義書に戻る](../requirements.md)

S-01〜S-24の全画面・モーダルについて、要件定義段階の骨組みレベルでワイヤーフレームをまとめる。実際のUIデザイン（配色・フォント・詳細CSS）の決定前段階の「叩き台」として、ASCIIアート風のレイアウト図で画面内の要素配置・サイズ感を示し、補足としてMermaidのブロック図（要素の関係性）も併記する。各画面の項目は対応する[機能別要件定義書](../requirements.md#5-機能要件)の内容に基づく。

---

## 共通ヘッダー（#257）

- 直下の関連機能タブは枠・角丸・塗りつぶしのないテキスト表示へ整理し、選択中だけ青い下線と文字色で示す（#370）。押せる高さはPC44px以上、スマホ40px以上。タブ順、キーボード操作、必要時の折り返し、スクロール追従は維持する。下部ナビの表示は後述の「下部の主要ナビゲーション（#462）」に従う。

- スクロール時はタイトルバーと、その直下にある在庫管理・家計簿・献立表の関連機能タブを一体で画面上部に残す（#364）。タブのない画面はタイトルバーだけを残す。320/390/1280pxで全タブとタイトルバー内の操作を維持し、折り返し後の高さにも対応する。本文は通常どおりスクロールし、モーダルは追従領域より前面に表示する。

世帯所属後の各画面では、白地のタイトルバーに左からシェファミロゴ（家のアイコン＋「シェファミ」。481px以上では補助表記「HomeLog」を併記）、通知、設定、アカウント名ボタン（人物アイコン＋ログイン本人の表示名）を全幅で1段に並べる（#462）。アカウント名ボタンを押すと「アカウント」ダイアログを開き、アカウント設定（`/settings/account`）とログアウトを利用できる。

- 表示名は `GET /api/auth/me` から取得し、メールや世帯の別メンバー名は代用しない。
- 長い名前は1行で省略し、DOMとtitle属性に全文を保持する。アカウント名ボタンは内容に合わせた幅とし、最大幅を`clamp(96px, 32vw, 144px)`に抑える。320pxでも操作部品とページ全体が横にはみ出さない。
- 取得中は「読み込み中…」、失敗時は「アカウント名を取得できません」。取得状態によらず、設定とアカウント名ボタンからのログアウトを利用できる。
- 「アカウント」ダイアログは閉じるボタン・Escape・背景クリックで閉じ、アカウント名ボタンへフォーカスを戻す。開いている間はダイアログ内でTab移動を循環させる。
- 世帯未所属画面へのヘッダー追加や、名前編集・全文表示専用UIは対象外。

### 下部の主要ナビゲーション（#462）

- 白地・5等分で画面下端に固定し、左からホーム（`/`）・献立（`/menu`。読み上げ名は「献立表」）・在庫（`/zaiko`）・家計簿（`/kakeibo`）・その他を、アイコン上・文字下で表示する。選択中は青い文字と太字で示し、操作領域は44px以上とする。
- 関連画面でも選択先は1つに定める（レシピは献立、割り勘・口座・固定費・イベント・カテゴリーは家計簿、買い物リストは在庫、設定・世帯設定は「その他」）。
- 「その他」は「その他の設定・管理」ダイアログを開く。表示設定・世帯設定・カテゴリー管理・固定費・口座・カード管理・割り勘・イベント・レシピ・買い物リストの9導線を置き、通知・本人名・ログアウト・アカウント設定は置かない（タイトルバー側で扱う）。
- ダイアログはリンク選択・画面遷移・閉じるボタン・Escape・背景クリックで閉じ、閉じたときは「その他」ボタンへフォーカスを戻す。「アカウント」ダイアログとは同時に開かない。

## S-04 トップ画面（生活ダッシュボード＋カレンダー）

日付詳細は `GET /api/dashboard/day-detail?date=YYYY-MM-DD`（#446/#431）を利用する。既存月間APIは維持し、月間には日付とカテゴリの有無、実額・明細はS-19に分離する。

対応: [F06_kakeibo_event](features/F06_kakeibo_event.md), [F12_kakeibo_household_summary](features/F12_kakeibo_household_summary.md), [F13_kakeibo_income](features/F13_kakeibo_income.md), [F07_zaiko_inventory](features/F07_zaiko_inventory.md), [F08_zaiko_shoppinglist](features/F08_zaiko_shoppinglist.md), [F10_kondate_menu](features/F10_kondate_menu.md)

- 月間は7列を保ち、日付とイベント→収入→支出→固定費の固定順で各1dot（最大4）を表示する。同カテゴリ複数件でも増やさず、dot＋文字の4凡例を添える。日付ボタンの読み上げにも有無を含める。名前・金額はS-19へ分離する。
- 表示設定OFFのイベント・収入・支出はdotと日付読み上げから除外する。固定費トグルは追加しない。S-19の取得内容は設定から独立。月移動中・取得失敗・再試行を区別し、旧月応答は破棄する。
- 通知アラームはトップナビゲーションに配置し、通知有効な繰り返しイベントの当日発生件数をバッジで表示する。カレンダー内には通知件数を表示しない。取得中は読み込み状態、取得失敗時はエラー状態を件数と区別して表示する。
- モバイルではカレンダーと有効なカードを保存順に1列へ積み、横方向のスクロールや固定ナビゲーションとの重なりを生じさせない。カードの表示/非表示設定、カード内項目、カード順は画面幅にかかわらず維持する。
- 「イベント別支出」カードは**期間セレクト（今日／今月／今年、デフォルト今年）**を持つ。「年間投資」は投資専用集計ではなく、暦年（今年）のイベント別支出を意味する。他のカードにイベント別支出を含めない。
- 未精算は「受取予定（自分が立て替えて相手から貰う分）」と「支払予定（自分が負担して相手に払う分）」を分けて表示する。
- 「個人の財政」カードは自分が所有する口座の残高合計を表示し、その下の行に「口座・カード管理を見る」リンク（S-15、`/accounts`）を配置する。読み込み中・取得失敗・口座未登録でもリンクを表示する。口座残高は本人のみ閲覧可能のため、このカードの内容もログインユーザー自身の情報のみで構成される（[common-notes.md](common-notes.md) 2章、[F11_kakeibo_account](features/F11_kakeibo_account.md)参照）。
- イベント別支出には全イベントではなく、**表示対象として選択したイベント（`show_on_dashboard` = true）のみ**を表示する。ON/OFFはS-18登録モーダル・S-09一覧から直接開く編集モーダル内で登録者が他の項目と一緒に保存する（[F06_kakeibo_event](features/F06_kakeibo_event.md) 4章参照）。
- 「買い物・在庫」カードは買い物リストを「品名／値段」、在庫リストを「品名／残数」の見出し付き2列で表示する。買い物は未購入のみ、在庫は残数と閾値以下の「（不足）」を表示する。値段は現在の参考値を桁区切りの円表示（0は「0円」、未設定は「未設定」）とし、数量との乗算はしない。在庫欄には値段を表示しない。品名とカード末尾にリンクを設けず、管理画面へは主要ナビゲーションから移動する。先頭8件と残件数、読み込み中・空・取得失敗、表示設定とカード順を維持し、長い品名と値は320pxでも全文を折り返して横にはみ出させない。「よく使う品目」は廃止する。
- 「今日の状況」カードは「今週の献立」「イベント」の2行に件数だけを表示する（0件も「0件」と表示する。#462）。各行はボタンで、押すと当日のS-19日付詳細を開き、閉じると押した行へフォーカスを戻す。今日の収支はカードに表示せず、S-19の収支欄で確認する。献立・イベントの表示設定が両方OFFのときはカード自体を表示しない。
- 今週の献立のレシピ詳細は、S-19の献立欄にあるレシピ行から既存レシピ詳細モーダルを閲覧専用で開く。編集・削除ボタンは表示しない（S-12では従来どおり表示）。自由メモ・削除済みレシピは操作できない文字列として表示する。
- レシピ取得中はレシピ行の多重操作を防ぎ、取得失敗・対象消失はS-19内にメッセージで表示する。詳細は閉じるボタン・Escape・背景クリックで閉じ、元のレシピ行へフォーカスを戻す。モーダル内部のクリックでは閉じない。長いタイトル・材料・手順は狭い画面でも折り返す。レシピ詳細は上部44pxの明示×を初期フォーカスとし、長文の冒頭から表示する。上部の閉じるをスクロール中も利用でき、末尾の「閉じる」も維持する。Tab移動先はモーダル内スクロールで見える状態にする。
- S-19のイベント欄を展開して対象行から閲覧専用S-24を開く。編集・削除ボタンや編集遷移は提供しない。
- 各カードの数値・リンク先は、対応する各機能画面の情報をそのまま参照する（新たな計算ロジックは持たない）。
- 「収支」（S-19の収支欄）は、ログインユーザー本人のその日の収入合計－支出合計。支出側の世帯合計対象フラグの有無に関わらず本人が登録した全件を対象とし、他メンバーの収入・支出は権限方針上参照できないため常に本人個人の収支となる（世帯合計支出とは別の指標。[common-notes.md](common-notes.md) 8章、[F13_kakeibo_income](features/F13_kakeibo_income.md)参照）。
- どのカード（今日の状況／買い物・在庫／個人の財政／今月のお金／イベント別支出／カレンダー）を表示するかに加え、カード内の項目単位でも設定画面（S-21）でユーザーごとに表示を選択できる。カレンダーは表示ONなら最上部、OFFなら非表示とする。全カードを非表示にした場合は設定画面への案内を表示する。
- S-21のチェックリスト下には有効カードをコンテナとして並べる編集グリッドを表示する。ドラッグ操作でカード順を変更でき、キーボード利用者には上へ／下へ移動ボタンまたは同等の操作を提供する。保存時に表示設定とカード順を同一トランザクションで保存し、成功後はS-04へ遷移する。失敗時はS-21に留まり、変更内容を保持してエラーを表示する。

## S-05 家計簿一覧画面

#422の独立UI部分：履歴は初期全期間・新しい順を維持し、キーワード（用途/収入内容）・収支種別・対象月・既存カテゴリーで絞り込む。月未選択は全期間、検索・月の解除はその2条件だけを解除する。履歴期間と「当月サマリー（年月）」を区別し、当月収入・支出・差額を表示する。履歴の絞込で当月集計は変えない。前回口座は同じbrowser内で利用者別・収入/支出別に成功した選択を記憶し、新規登録の初期候補とする（S-06/S-22参照）。


対応: [F03_kakeibo_expense](features/F03_kakeibo_expense.md), [F04_kakeibo_warikan](features/F04_kakeibo_warikan.md)（未精算サマリー）, [F05_kakeibo_fixedcost](features/F05_kakeibo_fixedcost.md)（固定費予定サマリー）, [F06_kakeibo_event](features/F06_kakeibo_event.md)（イベント支出サマリー）, [F12_kakeibo_household_summary](features/F12_kakeibo_household_summary.md)（世帯合計対象額サマリー）, [F13_kakeibo_income](features/F13_kakeibo_income.md)（収入一覧タブ）


## S-19 日次詳細モーダル

トップ画面の日付から開く閲覧ハブ。取得は `GET /api/dashboard/day-detail?date=YYYY-MM-DD`。認可・実績/予定・6状態は[API設計書](api-design.md)を正とし、ホーム表示設定から独立する。

対応: [F06_kakeibo_event](features/F06_kakeibo_event.md)、[F03_kakeibo_expense](features/F03_kakeibo_expense.md)、[F05_kakeibo_fixedcost](features/F05_kakeibo_fixedcost.md)、[F10_kondate_menu](features/F10_kondate_menu.md)

```text
┌─────────────────────────────────┐
│ 2026-07-10 の詳細           [ × ]│
├─────────────────────────────────┤
│ 今週の献立 3件               ＋ │
│ イベント 2件                 ＋ │
│ 収支 4件                     ＋ │
│ 固定費 1件                   ＋ │
│ （全閉で開始、複数を独立展開）    │
│ [ 閉じる ]（本文末尾、固定しない） │
└─────────────────────────────────┘
```

- 見出しは献立→イベント→収支→固定費の順。全閉で開始し、複数を独立展開できる。件数はAPI配列長、収支は収入明細数＋支出明細数。差額0円でも明細があれば0件としない。0件でも見出し・空説明・導線を残す。取得中・HTTP失敗は0件にせず、再試行を用意する。
- 献立はAPIのweekStartDateを対象週とし、レシピ行から既存認可GET /recipesでID照会して閲覧専用詳細へ。自由メモ・削除済みは文字表示。照会中の連打を抑止し、失敗/対象消失は説明する。「この週の献立を編集」は対象週の献立表へ遷移する。
- イベント行から既存認可GET /eventsでID照会してS-24へ。発生日は選択日、原本eventDateは変更しない。未取得情報は推測しない。「イベントを追加」はイベント画面へ遷移する。
- 収入・支出・差額は展開した収支欄だけに置き、本人実績明細と分けて表示する。「支出を登録」は家計簿へ遷移する。固定費予定額や再掲した計上記録は日次収支へ再加算しない。
- 固定費は現在の予定額と、postedの場合だけ計上記録の実額・支出日を分離表示する。6状態はF05の固定ラベルを表示し、FEで再判定しない。unknownに私的な実額・抑止の存在を補完しない。「支出に計上済み」は記録作成済みであり、銀行引き落とし・カード決済・精算の完了ではないと説明する。
- 右上×は本文スクロール中も利用可能。末尾の非固定「閉じる」・背景・Escでも閉じる。内部操作・展開・スクロールでは閉じない。320/390/1280pxで横はみ出しを防ぎ、safe-areaと44px程度の操作領域を確保する。
- 子Event/Recipeは親overlayの兄弟として表示し、子表示中は親をinertにする。共通useDialogで最上位だけがEsc/Tabを処理し、最後の可視modalを閉じるまで背景位置を保つ。子closeで元行、親closeで日付起点へ復帰する。日付変更・再表示は全閉に戻し旧応答を破棄する。

## S-10 在庫の自動消費入力（#329）

登録・編集モーダルの閾値欄の後に、次を縦配置する。

```text
1日の消費量（任意） [0.2]
空欄の場合は自動消費しません
[自動消費：オン / オフ] （role=switch）
毎日1:00（日本時間）に減ります。開始・再開は翌日から。
停止・消費量変更時は到来済みの未処理分を旧設定で精算します。
[保存] [キャンセル]
```

number入力はstep=0.1/min=0.1/max=99999.9。空欄でスイッチはオフ・無効、オフにしても消費量は保持する。登録初回入力でオン、その後の選択は維持する。詳細に「自動消費：未設定／0.2／日・オン／0.2／日・オフ」を追加する。一覧は品名・在庫数・閾値の3列のままとし、行ボタン内にスイッチは置かない。

1280/390/320pxで説明を折り返し、モーダル内の縦スクロールで保存へ到達できる。Tab巡回、Spaceでの切替、Escape・背景クリック、通信中の無効化とフォーカス復帰を維持する。保存失敗はrole=alertで入力を保持し、保存成功後の一覧取得失敗では保存を再送しない。
