# デモ環境（2アカウント切り替え）設計書

- Issue：#529
- 作成日：2026-11-14
- 状態：ユーザー確認待ち

## 1. 目的

README から誰でもシェファミを試せるようにする。来た人は登録なしでデモを始め、同じ世帯の2人（デモ太郎・デモ花子）を切り替えて、「本人だけに見えるデータ」と「世帯で共有するデータ」が分かれていることを体験できる。

### うまくいった状態

- README のリンクから、迷わず2人分の画面を試せる。
- 他の人の操作やいたずらの影響を受けず、デモが壊れたままにならない。
- 本番の利用者データ・本番の動作に影響しない。デモ用の外部サービスの費用が発生しない。

### やらないこと

- 全員で共有する固定のデモアカウント（パスワードを README に載せる方式）。
- デモから本番アカウントへの引き継ぎ。
- 2人を1つのタブで同時に表示すること（別ブラウザやシークレットウィンドウで開いてもらう）。

## 2. 全体の作り

### 2-1. 環境

| 項目 | 本番 | デモ |
| --- | --- | --- |
| Worker | `homelog-backend-workers` | `homelog-demo`（新規） |
| URL | `https://homelog-backend-workers.nyproducts.workers.dev` | `https://homelog-demo.nyproducts.workers.dev` |
| D1 | `homelog-db` | `homelog-demo-db`（新規） |
| R2（レシピ画像） | あり | なし |
| Workers AI | あり | なし |
| Google Vision のキー | あり | 設定しない |
| `DEMO_MODE` | 未設定 | `"true"` |
| Cron | 既存の2本 | 既存の2本 ＋ 1時間ごとのデモ削除 |

- プログラムと画面のビルドは本番と同じものを使い、`wrangler.toml` の `[env.demo]` でデモ用の名前・D1・変数・Cron を上書きする。
- デモ用の機能（`/api/demo/*`、帯の表示、機能の停止）は `DEMO_MODE === "true"` のときだけ動く。本番では `/api/demo/start` などは 404 を返す。
- マイグレーションは本番・デモで共通。デモ用に追加するテーブルは、本番では空のまま使われない。
- デモの `JWT_SECRET` は本番と別の値を `wrangler secret put JWT_SECRET --env demo` で設定する（値はリポジトリ・チャットに出さない）。本番のトークンはデモで、デモのトークンは本番で使えない。
- パスワード再設定メールの変数（`PASSWORD_RESET_MAIL_ENABLED` など）はデモでは `"false"` にし、送信用の秘密情報も設定しない。

### 2-2. 公開と更新

- デモは本番と同じタイミング（ユーザーの「本番に出して」）で更新する。
- 初回の作成（Worker・D1・マイグレーション）と更新は、手元から `npx wrangler d1 migrations apply DB --remote --env demo` と `npx wrangler deploy --env demo` で行う。
- Cloudflare の自動デプロイ（Workers Builds）への接続は、ダッシュボードでの操作が必要なため、この設計の範囲外とする（必要になったらユーザーに依頼する）。
- 手順は `docs/deployment.md` に追記する。

### 2-3. データの寿命

- デモ世帯は作成から24時間で期限切れになる。
- 1時間ごとの Cron（`0 * * * *`、デモ環境のみ）が、期限切れのデモ世帯と、その2人に関わる全テーブルの行を削除する。
- 今の `scheduled` は「`0 15 * * *` 以外なら在庫の自動消費も行う」作りのため、Cron 式ごとに処理をはっきり分ける（`0 * * * *` ではデモの削除だけを行い、既存の2本の動きは変えない）。
- 期限切れ後、削除までの間（最大1時間）は、デモ利用者の API 呼び出しを 401 にする（`DEMO_MODE` のときだけ、認証のたびに期限を確かめる。本番では確かめる処理を行わない）。

### 2-4. 大量アクセス対策

- `POST /api/demo/start` は、同じ接続元（`CF-Connecting-IP`）から1時間に5回まで。既存の `rate_limit_counters`（`lib/rate-limit.ts`）を使う。超えたら 429。
- 同時に存在できるデモ世帯は300件まで。超えたら 503 と「混み合っています。時間をおいて試してください」。
- 既存の回数制限（ログイン・URL登録など）はデモでもそのまま効く。

## 3. データ

### 3-1. 追加するテーブル

`demo_households`（マイグレーションを連番で追加）

| 列 | 型 | 説明 |
| --- | --- | --- |
| `household_id` | integer, PK, `households.id` への参照 | デモ世帯 |
| `primary_user_id` | integer, `users.id` への参照 | デモ太郎 |
| `partner_user_id` | integer, `users.id` への参照 | デモ花子 |
| `expires_at` | text（ISO 8601, UTC） | 期限 |
| `created_at` | text | 作成日時 |

- `expires_at` に索引を付ける（削除処理と件数確認で使う）。
- 「この利用者はデモか」は、`primary_user_id` または `partner_user_id` に一致する行があるかで判定する。`users` には列を足さない。

### 3-2. デモ利用者

- 表示名：「デモ太郎」「デモ花子」。
- メール：`demo-<乱数>-taro@example.com` / `demo-<乱数>-hanako@example.com`（RFC 2606 の予約ドメイン。メールは送らない）。
- パスワード：誰も知らない乱数からハッシュを作る。メールとパスワードではログインできない。
- 世帯名：「デモ家」。

### 3-3. 見本データ

日付はデモを始めた日（JST）を基準に「今月」で作る。名前・店名はすべて架空のもの。

| 種類 | デモ太郎 | デモ花子 |
| --- | --- | --- |
| 本人だけ：口座 | みどり銀行・クレジットカード | さくら銀行・交通系IC |
| 本人だけ：収入・支出 | 給与、書籍・ランチ・趣味など | 給与、美容院・カフェ・服など |
| 本人だけ：固定費・予定 | スマホ代（個人）、「歯医者」（個人） | ジム会費（個人）、「友人とランチ会」（個人） |
| 2人のあいだ：割り勘 | スーパー6,000円を立替。花子の負担3,000円 | 日用品2,400円を立替。太郎の負担1,200円 |
| 世帯で共有 | 在庫（卵・牛乳・お米・トイレットペーパー）、買い物リスト、レシピ3件（お気に入りあり）、今週の献立、世帯の固定費「家賃」（2人で折半）、世帯の予定「誕生日会」 | 左と同じ |

- 個人／世帯は、固定費・予定の `owner_user_id`（NULL=世帯共有）で表す。
- 家計簿カテゴリー・在庫カテゴリー・収入カテゴリーは、通常の世帯作成と同じ既定のものを作る。
- 作成は `lib/demo-seed.ts` の1つの処理で行い、D1 の `batch` にまとめる。途中で失敗したら何も残さない。1回のデモで約60行。

### 3-4. 削除

- `lib/demo-cleanup.ts` が、期限切れのデモ世帯ごとに、世帯・2人に関わる全テーブルの行を、外部キーの順に1つの `batch` で削除する。デモ中に利用者が追加した行（割り勘のコメント、世帯外の精算相手、リフレッシュトークンなど）も含む。
- 削除の対象は `demo_households` に載っている世帯と利用者だけ。それ以外の行には触れない。

## 4. API

| メソッド・パス | 認証 | 説明 |
| --- | --- | --- |
| `GET /api/demo` | 不要 | `{ enabled: boolean }`。デモ環境なら true。本番でも 200 で false を返す（画面が出し分けに使う） |
| `POST /api/demo/start` | 不要 | デモ世帯・2人・見本データを作り、デモ太郎のトークン（ログインと同じ形）を返す。201 |
| `POST /api/demo/switch` | 必要 | 今の利用者がデモ利用者で、相手が同じデモ世帯のもう1人のときだけ、相手のトークンを返す。今のリフレッシュトークンは失効させる。それ以外は 404 |
| `GET /api/auth/me`（既存に追加） | 必要 | デモ利用者なら `demo: { expiresAt, partnerName }`、それ以外は `demo: null` を足す |

- `DEMO_MODE` が無いとき、`/api/demo/start` と `/api/demo/switch` は 404。
- エラーは既存の `errorResponse` の共通形式にする。

### 4-1. デモで止める機能

`DEMO_MODE` のとき、次の API は 403、コード `DEMO_DISABLED`、文言「デモでは使えません」を返す（処理の前に止める）。

- `POST /api/auth/register`
- `PUT /api/auth/password`、`PUT /api/auth/email`
- `POST /api/auth/account/deletion`、`POST /api/auth/account/deletion/cancel`
- `POST /api/auth/password-reset/request`、`POST /api/auth/password-reset/confirm`
- `POST /api/households`、`POST /api/households/join`、`POST /api/households/leave`、`POST /api/households/invite-code/regenerate`
- `POST /api/recipes/ocr/upload`、`POST /api/recipes/ocr/analyze`

表示名の変更（`PATCH /api/auth/account`）、家計簿・割り勘・固定費・口座・在庫・買い物・献立・レシピ（手入力・URL登録）・表示設定などの通常の操作は使える。URL登録は本番と同じ安全対策・回数制限のまま使う。

## 5. 画面

### 5-1. ログイン画面

- `GET /api/demo` が `enabled: true` のときだけ、ログインボタンの下に「デモを試す（登録不要）」ボタンと説明「架空の2人の世帯で、24時間お試しできます」を出す。
- 押すと `POST /api/demo/start` → トークンを保存 → ホームを開く。429・503 のときは文言を表示する。

### 5-2. デモ中の帯

- `me.demo` があるとき、全画面のヘッダーの下に帯を出す：「デモ中：デモ太郎として表示しています（残り◯時間）」と、ボタン［デモ花子に切り替える］［見どころ］［デモを終わる］。
- 切り替え：`POST /api/demo/switch` → トークンを保存 → ホームを開き直す（ページを読み込み直し、前の人の表示を残さない）。
- 見どころ：次の4行を出す。
  1. 家計簿・口座：太郎と花子で中身がまったく違う（本人だけのデータ）
  2. 割り勘：自分の立替は、相手の画面で「支払う分」として見える
  3. 在庫・買い物リスト・献立・レシピ：どちらから見ても同じ。片方が追加すると、もう片方にも出る
  4. 予定・固定費：「世帯」のものは2人に、「個人」のものは本人だけに見える
- デモを終わる：既存のログアウトと同じ。
- 390px・320px でも1画面に収まるよう、狭い幅ではボタンを折り返す。

### 5-3. 止めた機能

- 止めた API の文言（「デモでは使えません」）は、既存のエラー表示の仕組みでそのまま出る。
- アカウント設定画面には、デモ中だけ「デモでは表示名以外は変更できません」と注記する。

### 5-4. 期限切れ

- 期限切れで 401 になると、既存の仕組みでログイン画面に戻る。そこから新しいデモを始められる。

## 6. README

- 冒頭近くに「デモ」の節を追加し、デモの URL、始め方（「デモを試す」）、2人の切り替えと見どころ、24時間で消えること、止めている機能、2人を並べて見たいときは別ブラウザかシークレットウィンドウを使うことを書く。
- パスワード等の認証情報は書かない（そもそも存在しない）。

## 7. テスト

- バックエンド（Vitest ＋ miniflare の D1）
  - `GET /api/demo`：`DEMO_MODE` の有無で true/false。
  - `POST /api/demo/start`：世帯・2人・見本データができ、太郎のトークンが使える。`DEMO_MODE` なしで 404。回数制限（6回目で 429）、上限（300件で 503）。
  - `POST /api/demo/switch`：太郎→花子→太郎と切り替わる。元のリフレッシュトークンが失効する。デモでない利用者・別のデモ世帯の利用者は 404。
  - 見本データの見え方：太郎と花子で口座・支出が分かれ、在庫・レシピは同じ。割り勘が相手側に「支払う分」として出る。
  - 止める機能：4-1の各 API が `DEMO_MODE` で 403、`DEMO_MODE` なしでは従来どおり。
  - 削除：期限切れのデモだけが全テーブルから消え、期限内のデモと通常の世帯・利用者の行は残る。期限切れの利用者の API は 401。
  - Cron：`0 * * * *` ではデモの削除だけが動き、在庫の自動消費などは動かない。既存の2本の動きは変わらない。
- フロントエンド（Vitest ＋ msw）
  - デモボタンの出し分け、開始・切り替え・429/503 の表示、帯・見どころ・アカウント設定の注記。
- E2E（Playwright、ローカルの D1、`DEMO_MODE=true` で起動する設定を追加）
  - デモを始める → 太郎の口座を見る → 花子に切り替える → 口座が違い、在庫が同じ → 割り勘が「支払う分」で見える。1280 / 390 / 320px で帯の表示崩れがない。
- 本番相当（`DEMO_MODE` なし）の E2E は既存のままで、デモボタンが出ないことを1件追加する。
