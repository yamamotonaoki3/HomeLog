# タイトルバーと関連機能タブの追従 実装計画

> 実行: superpowers:executing-plans。ユーザー選択済みの案2を、この専用ブランチでTDD実装する。

**Goal:** スクロール後もタイトルバーと関連機能タブを両方表示・操作できるようにする。
**Architecture:** 共通AppLayoutのヘッダーとnavを一つのstickyラッパーへまとめ、自然な高さで折り返しに対応する。モーダルより低い重なり順を使う。
**Tech Stack:** 既存React / TypeScript / CSS / Playwright。新規依存なし。
**Spec:** https://github.com/yamamotonaoki3/HomeLog/issues/364 とユーザーが選択した案2。

## 制約・レビュー観点

- frontendのみ。API・DBは変更しない。
- タイトルバー内の操作と全タブ、タブ順・選択中表示・折り返し・下部ナビを維持する。
- 1280/390/320pxで確認する。タブがないページでも共通タイトルバーは追従する。
- モーダルより奥、本文より手前。固定高・JSでの高さ計測は使わない。
- 実スクロール量と座標・クリックを検証する。単にtoBeVisibleが通るだけでは完了にしない。
- コミット・push・本番反映は別途ユーザーの指示を待つ。

## 目的
在庫管理・家計簿・献立表で下へスクロールしても、HomeLogのタイトルバーと直下の関連機能タブを両方操作できるようにする。ユーザーは「タイトルバーとタブを両方残す」案を選択済み。

## 仕様・実装方針
- 共通レイアウトのタイトルバーと関連機能タブを一つの領域にまとめ、position: stickyで画面上端へ追従させる。
- タイトルバー内のHomeLog・通知・設定・ログアウト、直下の全タブを残す。
- 適用範囲はAppLayout配下。タブがないトップ・設定等ではタイトルバーのみ追従する。
- 高さの固定値やJSによる高さ計測を使わず、タブの折り返しとアカウント名表示に追従する。
- 初期表示で本文を覆わず、スクロール中は本文より手前、モーダルより奥に表示する。下部ナビは従来どおり。
- 新しい技術・依存・API・DB変更なし。

## 実装計画
1. 1280/390/320pxのE2Eを先に追加。各3領域で十分なスクロール量を確保し、window.scrollYが変化した状態でもヘッダー・全タブの座標が画面内であること、タブのクリック遷移が動くことを確認し、現状のredを確認する。
2. AppLayoutへタイトルバーと関連機能タブの共通ラッパーを追加し、CSSのsticky/top/z-indexを設定する。既存のタブ順・選択中表示・折り返しを維持する。
3. モーダルが固定領域より前面に表示されることと、先頭時の本文配置・横はみ出しをE2Eで検証する。テストはconsole-guardを利用する。
4. 関連仕様書へ画面上部の追従動作を記録する。
5. frontend全体のlint/test/buildと対象E2Eを実行し、専用DBの後始末を確認する。Codexレビュー後にユーザーへ確認結果を報告する。
