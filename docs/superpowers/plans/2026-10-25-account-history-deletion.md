# 履歴を保持する口座削除 実装計画

> 実行: superpowers:executing-plans。ユーザー合意済みの履歴保持方式をTDDで実装する。

**Goal:** 割り勘などの過去取引があっても、不要な本人所有の口座を履歴保持で削除できるようにする。
**Architecture:** 既存のdeleted_atとDBトリガーを維持し、削除batchの履歴判定を拡張する。固定費・子カード残高の利用中制限だけを削除禁止条件に残す。
**Tech Stack:** 既存Hono / Drizzle / D1 / Vitest / Playwright。依存・マイグレーション追加なし。
**Spec:** Issue #368（API）と#371（画面、#368マージ後）。ユーザー合意: 履歴を残して一覧・残高合計・新規入力から口座を外す。

## 制約・レビュー観点

- 本人認可・新規利用禁止・取引と削除の原子性を維持する。
- 精算義務・過去の支出/収入/チャージ・子カード・残高を削除時に変更しない。
- 固定費利用中・残高が0でない子カードは従来どおり削除不可。
- 支払報告済みの削除口座は、既存仕様どおり精算確定時に口座なしとして扱う。
- 履歴参照がなければ既存の物理削除を維持する。
- 既存の削除済み口座に紐づく明細の編集・削除制限（409）は変更しない。
- テストは専用ローカルD1だけを使う。本番データを直接削除しない。
- 在庫カテゴリー絞り込みは#369、上部タブ整理は#370へ分離する。
