# 技術スタック構成

[← 要件定義書に戻る](requirements.md)

本番は Cloudflare Workers 上で動く TypeScript 版（`backend-workers/` ＋ `frontend/`）である。当初の Java/Spring Boot 版（`backend/`）は移行元として残しているが、本番では使っていない（2026-10 時点）。バージョンは各 `package.json` を正とする。

開発・テスト・ビルド用Node.jsは **24.22.1 LTS**。GitHub Actionsはルートの[.node-version](../.node-version)、Cloudflare Workers Buildsは[backend-workers/.node-version](../backend-workers/.node-version)で指定する。各 `package.json` の `engines.node` は `>=24.22.1 <25`。これは本番のWorkersランタイムのバージョン指定とは異なる。[導入・更新手順](deployment.md#nodejsの導入更新)参照。

## 運用方針

- 在庫の日次自動消費は全世帯に対するセットベースSQL（INSERT ... SELECT と条件付きUPDATE）を1つのD1 batchで実行する。対象件数によらず固定2文とし、無料プランのWorker実行あたりクエリ数を抑える。失敗時はリスト追加・数量・処理日をまとめてロールバックする。
- 家族利用の段階では Cloudflare の無料枠の範囲で運用する。
- 利用規模が大きくなった場合は、D1 の容量・Workers の実行時間制限を踏まえて構成を見直す。

## Workers開発用の間接依存の上書き（#347）

backend-workers/package.json の overrides は、親パッケージのダウングレードを避けて次の監査通知を解消するために限定して指定する。

| 対象の依存経路 | 上書き先 | 理由 |
| --- | --- | --- |
| Miniflare → sharp | 0.35.5 | libheif・librsvgの脆弱性修正 |
| Miniflare → undici | 7.30.1 | TLS検証回避・EventSourceや圧縮応答等のDoS・SRI検証回避の脆弱性修正 |
| @cloudflare/vitest-pool-workers → zod | 直接依存のzodと同じ版 | テストランナーが固定指定する古いzodを、本番依存と同じ修正済み4系へ揃える（#351） |
| @esbuild-kit/core-utils → esbuild | 0.25.12 | 開発サーバーのCORS脆弱性修正（GHSA-67mh-4wv8-2f99） |

Workersのテスト用パッケージが古いMiniflareを固定指定し、Drizzle Kit配下のcore-utilsがesbuildを ~0.18.20 に制限しているため、通常のロック更新だけでは解消しない。特にesbuildは親の指定範囲を超えるため、更新時はWorkers全テストとDrizzle Kitの設定読み込み・マイグレーション生成を確認する。共有済みの drizzle/*.sql は編集せず、生成検証には一時出力先を使う。

親の依存条件が修正済みの子パッケージを利用できるようになったら、対象の上書きを外し、npm audit と上記の互換性検証を再実行して解除する。本番のWorkersランタイムそのものを変更する設定ではない。

## ビルド・Lint用依存の限定上書き（#441 / #442）

2026-11-07時点で親パッケージの最新版も脆弱な子依存を指定しているため、次の経路だけを `overrides` で上書きする。直接依存のダウングレードや、すべての `minimatch` に対する一括上書きは行わない。

| 対象 | 依存経路 | 上書き先 | 理由 |
| --- | --- | --- | --- |
| `frontend/` | workbox-build → glob | 14.0.4 | キャンセル後も探索が続く可用性問題（GHSA-3g3m-2fjr-6pw4）を修正。glob配下のminimatchも修正済み11.0.5へ解決される |
| `backend-workers/` | @typescript-eslint/typescript-estree → minimatch | 11.0.5 | パターン増幅によるDoS（GHSA-g3hv-75wg-m249）を修正 |

いずれも親の指定するメジャーバージョンを超えるため、更新時はクリーンインストール、全体のlint・型検査・テスト・ビルドと、PWA生成・Service Worker・Web Share Target・API除外設定のE2Eを確認する。Workboxは `globSync`、typescript-estreeは `minimatch` 関数を使用する。親の依存条件が修正版を許容するようになったら、該当する上書きを外して監査と互換性検証を再実行する。

`frontend/` の workbox-build → @rollup/plugin-node-resolve → deepmerge 4.3.1 には、GHSA-gcqx-w48m-w2h4（返却オブジェクトのプロトタイプ汚染）が残る。2026-11-07時点で公式修正版は未公開であり、監査除外や互換性未確認の置換で解消扱いにはしない。現行node-resolveでの呼出箇所は内部の既定設定を複製する `deepMerge({}, defaults)` で、アプリ利用者からの入力をここへ直接渡す経路は確認されていない。2026-11-07にユーザーが公式修正を待つ方針を承認したため、ローカルパッチや代替ライブラリは導入せず、#441を未完了のまま追跡する。公式修正版または親パッケージでの依存解消が公開されたら、監査とPWAの互換性検証を行って更新する。これは脆弱性そのものの解消や、監査通知の除外を意味しない。
